# video-annotator

Поэтапная обработка видео: **видеофайл → аудио → транскрипт → текстовая аннотация**.

## Возможности

- Поэтапная обработка с явными статусами `[OK]` / `[FAIL]` и прогресс-баром на каждом шаге
- **Два режима аннотации**:
  - `referat` (по умолчанию) — абстрактивный пересказ по алгоритму из 5 шагов
    через LLM: сканирование → маркировка тезисов → фильтрация 80/20 →
    написание своими словами → редактура и нейтральность;
  - `extract` — локальная экстрактивная выборка предложений (TF-IDF + MMR),
    работает без LLM.
- Регулируемая степень детализации аннотации: от максимально краткой (1) до детальной (5)
- **Ускорение на GPU**: CUDA-сборка whisper.cpp (RTX 5080 даёт ~31x реального времени против ~10x на CPU)
- Оценка ожидаемого времени и ETA на каждом этапе
- Полностью локально: ffmpeg + whisper.cpp, без API-ключей и интернета при работе
- Кэш промежуточных файлов (WAV и JSON транскрипта) — повторный запуск быстрее
- Кэш шагов 1-3 реферата (тезисы по блокам) — финальный текст перегенерируется
  за секунды вместо повторных вызовов модели

## Этапы

| # | Этап | Инструмент |
|---|------|-----------|
| 1 | Анализ входного файла (длительность, кодеки, наличие звука) | ffprobe |
| 2 | Извлечение аудио (16 кГц, моно, WAV) | ffmpeg |
| 3 | Транскрибация с таймкодами | whisper.cpp (whisper-cli) |
| 4 | Реферат: 5 шагов подготовки пересказа | LLM (opencode CLI) |

## Как готовится реферат (режим `referat`)

| Шаг | Что происходит | Как влияет на результат |
|-----|----------------|--------------------------|
| 1. Сканирование | по началу и концу записи определяются тема, проблема, цель, структура и ключевые понятия | задаёт рамку всего реферата |
| 2. Маркировка | транскрипт делится на блоки по ~2000 слов, из каждого выписываются тезисные утверждения (по связующим словам «следовательно», «таким образом» и т. п.) | отбрасываются примеры и отступления |
| 3. Фильтрация 80/20 | из тезисов убираются повторы, риторика, вопросы из зала, эмоциональные оценки, второстепенные детали | остаётся только несущая смысл часть |
| 4. Черновик | пишется текст **своими словами** со структурой «ТЕМА И ПРОБЛЕМА → ОСНОВНЫЕ АРГУМЕНТЫ → ВЫВОДЫ И РЕКОМЕНДАЦИИ», зеркалящей ход рассуждения автора | это пересказ, а не набор цитат |
| 5. Редактура | убираются оценки редактора, выправляются причинно-следственные связи, чистится язык | текст нейтрален и логичен |

## Установка

Быстрый путь — скрипт, он ставит ffmpeg, скачивает whisper.cpp и модель:

```powershell
powershell -ExecutionPolicy Bypass -File setup.ps1
powershell -ExecutionPolicy Bypass -File setup.ps1 -Model large-v3 -Gpu   # с CUDA
```

Ручная установка:

1. **Python 3.10+** — только стандартная библиотека, пакеты не нужны.
2. **ffmpeg** — `winget install Gyan.FFmpeg`
3. **whisper.cpp** — скачать `whisper-bin-x64.zip` из
   [релизов](https://github.com/ggml-org/whisper.cpp/releases), распаковать в
   `tools/whisper/` (итого путь `tools/whisper/Release/whisper-cli.exe`).
   *Для GPU* дополнительно скачать `whisper-bin-win-cuda-12.4.0-x64.zip` и
   распаковать в `tools/whisper-cuda/` — пайплайн найдёт её автоматически.
4. **Модель whisper** — положить в `models/`:
   ```
   curl -L -o models/ggml-small.bin https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-small.bin
   curl -L -o models/ggml-large-v3.bin https://huggingface.co/ggerganov/whisper.cpp/resolve/main/ggml-large-v3.bin
   ```

Тяжёлые файлы (бинарники и модели, ~5 ГБ) исключены из git и не хранятся
в репозитории — их скачивает `setup.ps1`.

## Производительность (замеры на Ryzen 9 9950X3D + RTX 5080)

| Модель | CPU (16 потоков) | GPU (CUDA) | Время на 2:10:42 |
|--------|------------------|------------|------------------|
| `small` (465 МБ) | ~10x реального времени | ~31x | 13 мин → 4 мин |
| `large-v3` (2.9 ГБ) | ~3x | ~13x | 43 мин → 10 мин |

`large-v3` даёт заметно более чистый транскрипт на русском, поэтому для
качественной аннотации стоит использовать её вместе с `--device gpu`.

> CUDA-сборка `whisper-bin-win-cuda-12.4.0-x64.zip` работает на Blackwell
> (RTX 5080, compute 12.0) через PTX JIT, несмотря на более старый CUDA.
> При запуске whisper печатает `ggml_cuda_init: found 1 CUDA devices`.

## Использование

```bash
# базовый запуск (детализация 3 — умеренно, режим реферата)
python annotate.py video.mp4

# максимально краткая аннотация
python annotate.py video.mp4 -d 1

# детальная аннотация на GPU, сохранить в файл и транскрипт тоже
python annotate.py video.mp4 -d 5 --device gpu -o annotation.txt --save-transcript transcript.txt

# локальная экстрактивная аннотация (без LLM, мгновенно)
python annotate.py video.mp4 -d 3 --mode extract

# пересчитать транскрипт принудительно (например, сменив модель)
python annotate.py video.mp4 --model large-v3 --device gpu --force

# другие опции
python annotate.py video.mp4 --lang auto --model base --threads 8
```

### Уровни детализации (`-d` / `--detail`)

| Уровень | Псевдонимы | Объём | Содержание |
|---------|-----------|-------|-----------|
| 1 | `кратко`, `brief` | ~60 слов | одно краткое содержание |
| 2 | `сжато`, `short` | ~150 слов | + основные тезисы |
| 3 | `нормально` (по умолчанию) | ~300 слов | + разделы по хронологии, ключевые слова |
| 4 | `подробно`, `long` | ~600 слов | + таймкоды у тезисов, цитаты |
| 5 | `детально`, `detailed` | ~1000 слов | максимум разделов, цитат, ключевых слов |

### Прочие опции

- `--mode referat|extract` — способ аннотации (по умолчанию `referat`)
- `--llm-model MODEL` — модель LLM для пересказа (по умолчанию `opencode/minimax-m3.1-flash-free`)
- `--opencode-cli PATH` — путь к `opencode-cli.exe`
- `--save-trace FILE` — сохранить пошаговый разбор (шаги 1-5) в файл
- `--lang ru|en|auto` — язык речи (по умолчанию `ru`)
- `--model tiny|base|small|medium|large-v3` — модель whisper
- `--device auto|gpu|cpu` — где считать: `auto` берёт CUDA-сборку, если она есть
- `--threads N` — потоки CPU
- `--whisper-cli PATH` — путь к бинарнику whisper-cli
- `--force` — пересчитать транскрипт, проигнорировав кэш
- `--keep-wav` — не удалять промежуточный WAV
- `--work-dir DIR` — папка кэша (по умолчанию `.video-annotator/` рядом с видео)

## Самопроверка

```bash
python selftest.py
```

Проверяет парсинг уровней, формат времени, построение аннотации на всех
пяти уровнях (наличие нужных разделов и монотонный рост объёма), разбор JSON
транскрипта и обработку пустого входа. Видео и сеть не нужны.

```
## ТЕМА И ПРОБЛЕМА

Материал посвящён организации грудного вскармливания у младенца раннего
возраста и объясняет, как правила ключевых кормлений, нормы прибавки веса
и приёмы воспитания без слов обеспечивают малышу здоровье и спокойное
развитие. Задача лекции — научить маму учитывать возрастные особенности
ребёнка при кормлении, одновременно учитывая собственные потребности.

## ОСНОВНЫЕ АРГУМЕНТЫ

### Ключевые кормления как источник питания

1. Под ключевыми кормлениями имеются в виду кормление при засыпании...
2. Просыпание нужно ловить до того, как ребёнок откроет глаза...
...

## ВЫВОДЫ И РЕКОМЕНДАЦИИ

Грудное вскармливание — не только питание, но и воспитание...
```

Отличия от экстрактивного режима: текст написан **своими словами**,
сохраняет логику рассуждения автора, не содержит реплик из зала
и разговорных оборотов.

## Чем реферат лучше экстрактивной аннотации

Экстрактивный режим (`--mode extract`) выбирает готовые предложения из
транскрипта. Это быстро, но у него есть системные недостатки: дословные
фрагменты без контекста, обрывки на границах сегментов, реплики из зала
вместе с содержанием лекции, отсутствие причинно-следственных связей.

Рефератный режим (`--mode referat`) эти проблемы снимает:

| Проблема экстрактивного режима | Как решается в рефератном |
|-------------------------------|---------------------------|
| предложения копируются дословно | шаг 4 требует переформулировать тезисы своими словами |
| обрывки фраз на границах сегментов | шаг 2-3 работает со склеенными блоками и отбрасывает обрывки |
| реплики слушателей попадают в текст | шаг 3 явно отбрасывает вопросы из зала и обращения к аудитории |
| нет логики, только набор фраз | шаг 4 выстраивает «тезис → следствие → практический вывод» |
| разговорные обороты | чистятся на шаге 3 (слова-паразиты) и на шаге 5 (редактура) |
| нет завершённой мысли | шаг 5 связывает предложения, добавляя причинно-следственные связки |
| субъективные оценки | шаг 5 требует передавать позицию автора, без «я думаю» |

## Структура

```
video-annotator/
├── annotate.py            # точка входа (CLI, пайплайн, статусы)
├── selftest.py            # самопроверка без видео
├── setup.ps1              # установка ffmpeg, whisper.cpp и модели
├── pipeline/
│   ├── ui.py              # статусы этапов, прогресс, парсинг уровня детализации
│   ├── media.py           # ffprobe/ffmpeg: анализ и извлечение аудио
│   ├── transcribe.py      # whisper-cli: запуск, прогресс, чтение JSON
│   ├── referat.py         # абстрактивный реферат: 5 шагов подготовки пересказа
│   ├── llm.py             # клиент LLM через opencode CLI
│   └── summary.py         # локальная экстрактивная аннотация (TF-IDF + MMR)
├── tools/whisper/         # бинарники whisper.cpp (CPU)      → setup.ps1
├── tools/whisper-cuda/    # бинарники whisper.cpp (CUDA)     → setup.ps1
├── models/                # ggml-модели                      → setup.ps1
└── work/                  # промежуточные файлы (кэш)
```
